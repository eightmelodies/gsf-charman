# Guidelines for Working with Cline

## General Approach
- Always read the current file state before suggesting changes
- Make precise, minimal edits rather than large refactors
- Avoid ping-ponging on the same code - settle on a solution and move on
- If uncertain about the current state, ask or read the file first
- Avoid adding extraneous comments that simply describe what is already happening in the code
- When refactoring, adding features, or modifying existing code it's better to go slow and work in discrete steps rather than making sweeping changes all at once
- **Never remove existing code** unless explicitly instructed to do so or unless absolutely vital to the task being performed

## Communication
- Be direct about what's needed
- If a fix is simple, just make the change without over-explaining
